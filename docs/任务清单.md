## 二、静态化会影响什么（关键判断）

| 功能 | 静态站下的命运 | 说明 |
|---|---|---|
| 3D 场景 / 动画 / 交互 | 不受影响 | 全在浏览器；`/` 本来就 `ssr:false` |
| 路由 | 几乎无影响 | 全站只有一个路由 `/`，内容靠组件状态切换，不需要 SPA 嵌套路由 |
| 登录 | 技术上照常 | 纯 localStorage，无后端依赖 |
| 进度 / 收藏 / 成就 | 照常，但只在本机 | 换设备、换浏览器、清缓存就没了；文案要说明白 |
| 留言 | **做不了** | 静态站没有存储；未来用第三方（Giscus / Formspree / EmailJS）或接一个免费后端 |
| 分享预览 | 要改做法 | 不能靠 SSR 生成 head，需要在静态 `index.html` 里写死 meta + 一张 og 图 |
| 字体 | 已完成 | Google Fonts 改成自托管 woff2 |
| 构建产物 | 已改完 | SSR bundle → 纯静态文件夹（能直接拖到托管平台） |
| 服务端函数 | 无 | 全项目 `createServerFn` 用量 = 0，这是静态化最容易的地方 |

**"点点点"上线方案对比**

| 平台 | 操作 | 免费子域名 | 国内可达性 | 备注 |
|---|---|---|---|---|
| Cloudflare Pages（Direct Upload） | 拖 zip / 拖文件夹 | `xxx.pages.dev` | 较好 | 推荐；免费额度大、自带 CDN |
| Netlify Drop | 拖文件夹 | `xxx.netlify.app` | 一般 | 最简单，无需账号即可预览 |
| GitHub Pages | 建仓库 → 上传 | `xxx.github.io` | 时好时坏 | 需要 git，非"点点点" |
| Vercel | git 导入 | `xxx.vercel.app` | **国内基本不可用** | 现有配置就是它，建议弃用 |

**结论**：推荐 Cloudflare Pages Direct Upload，产物是一个 `dist/client/` 文件夹，以后更新 = 重新拖一次。不需要域名、不需要服务器、不需要付费。

## 三、登录：我的建议

**技术事实**：它是纯前端的"假门"——密码是 FNV-1a 哈希存 localStorage，验证问题是"做这个网站的人叫什么名字"。没有服务器校验，懂技术的人 10 秒绕过；而它的真实作用只是"给进度起个名字"。

**产品判断**：不建议保留为必经之门。三个理由：
1. 个人作品站的第一目标是让人 5 秒内看到 3D 岛，现在第一眼是一张要答对作者名字的表单，漏斗损失最大；
2. 静态站没有账号体系，密码不提供任何真实保护，只增加摩擦；
3. 项目最初的需求文档里本来就写着 "No sign-in"。

**推荐方案（B）**：**取消拦路表单，改为可选昵称**
- 打开 → 欢迎页 → Enter → 直接进入世界（默认身份 `Guest`）
- 世界内 header 保留一个"设置昵称"入口，填了之后进度/成就/收藏按该昵称存档
- 旧数据兼容：已有 `jenia:session:v1` 的访客自动沿用；`jenia:visited:v1` 旧共享 key 迁移一次
- 保留 `user.ts` 的 `visitedKey(user)` 契约不动，只把 `signIn()` 的校验拆成 `setNickname()`

**备选（C）**：干脆删掉所有身份概念，全站共用一个本地存档。改动更小，但多设备/多身份的乐趣没了。
**备选（A）**：保留登录，但瘦成"只填昵称，一键进入"（去掉密码和验证问题）。

## 四、任务清单（每个 = 一次会话）

### 阶段 A · 让它能静态上线

- [x] **A1 切换到 SPA 静态构建**
  目标：`npm run build` 产出纯静态文件夹，无 server bundle。
  做法：`vite.config.ts` 里 `tanstackStart: { spa: { enabled: true, prerender: { outputPath: "/index.html" } } }`，`nitro: false`；用 `@lovable.dev/vite-tanstack-config` 透传并实测输出。
  验收：产物里有 `index.html` + `assets/*`，没有 `server/`；`npx serve` 打开能进欢迎页并进世界。
  依赖：无。
  结果（2026-11-07）：**静态产物根是 `dist/client/`**（不是 `dist/`），内含 `index.html` + `assets/` + `fonts/` + `gallery/` + `favicon.ico` + `robots.txt`，共 8.1 MB。`dist/server/` 仍会生成（0.5 MB），那是 Vite 为预渲染 shell 跑的一次 SSR 构建；它不参与静态部署，但**不能从 build 脚本里删**——Lovable 云端用同一条 `npm run build`，在那边 `dist/server` 才是可部署的 worker。静态部署只上传 `dist/client/`。`spa.prerender.outputPath` 设为 `/index.html` 后不再生成 `_shell.html`，`/` 与 A4 的 `/* /index.html 200` 都指向同一个入口。实测：普通静态服务（node:http，无 rewrite）下 `/` 出欢迎页，点「进入」正常进 3D 世界（WebGL2 ready、canvas 1250x671），全程 0 个 404、0 个 console error（仅 three.js 两条 deprecation warning）。首次访客仍会被登录表单拦住——那是 B1 的活。

- [ ] **A2 清掉 SSR 专属件**
  目标：删/停用只对服务端有意义的文件，避免误导。
  范围：`src/server.ts`、`src/start.ts` 的 csrf 中间件、`vercel.json`、`src/routeTree.gen.ts` 里的 `ssr: true`（重新生成即可）。
  验收：构建无警告，页面行为不变。
  依赖：A1。
  注：**不阻塞 A4**。静态部署只上传 `dist/client/`，`dist/server/` 用不到；可后移到上线之后。

- [x] **A3 字体自托管 + 资源路径核查**
  目标：断网也不丑；所有静态资源在子路径下也不 404。
  结果（2026-11-07 12:51 补记）：字体部分其实 10:58 就做完了——`public/fonts/great-vibes-latin.woff2`、`nunito-latin.woff2` 已落盘，`src/styles.css` 写了 `@font-face`，`__root.tsx` 不再引 Google Fonts，全项目 grep 无 `fonts.googleapis.com` / `fonts.gstatic.com`。资源路径核查结论：`/fonts/`、`/gallery/`、`/favicon.ico` 都是根绝对路径，**必须部署在域名根**（Cloudflare Pages 的 `xxx.pages.dev` 满足），放到子目录会全挂；已记进交接文档第 12 节坑 7，本任务不需要再改代码。
  验收：devtools 里无跨域字体请求、无 404（A1 的静态服务实测已覆盖）。

- [ ] **A4 首次部署上线**
  目标：拿到一个可分享的 URL。
  做法：构建产物打 zip → Cloudflare Pages Direct Upload；补 `_redirects`（`/* /index.html 200`）；记录 URL 与上传步骤。
  验收：手机 4G 打开能进 3D；刷新不 404；把 URL 写进 README。
