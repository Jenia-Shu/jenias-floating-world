# 同步与记录规范

> 定于 2026-11-07 13:00，用户原话：
> 「你做的每一个东西都要同步到 GitHub 上面去」
> 「你做的一些东西，你要把它记录下来，还有我的想法把它记录下来，记录到 docs 那个文件夹里面」

这条规范覆盖旧文档里「不主动 git commit」的说法。除「提交」外，其余铁律（不 force push / rebase / amend / squash、一次只做一个任务、不顺手改设计文案、产品决策让用户拍板）继续有效。

---

## 1. 每完成一件事，必须同步到 GitHub

| 项 | 值 |
|---|---|
| 仓库 | `d:\mlsstu\Desktop\SELF\jenias-floating-world` |
| 远程 | `https://github.com/Jenia-Shu/jenias-floating-world.git` |
| 分支 | `main`（连接 Lovable） |

流程：

```
git add -A
git commit -m "<一句话说明这次做了什么>"
git push origin main
```

- **一件事一个 commit**，不要攒一堆再提交。
- 推到 `main` 会同步回 Lovable，必须保持可工作状态：改过代码就先 `npm run build` 或 `npm run dev` 验证再提交；跑不了就如实写「未验证」，不要假装测过。
- **仍然禁止** force push / rebase / amend / squash 已推送历史（`AGENTS.md`）。正常 fast-forward push 可以；若本地显示 `ahead N`，那些提交一并正常推送即可，不要改写。
- 推送失败（凭证、网络、权限）要如实说明，不要假装已经同步。
- 本机沙箱下 `npm test` 会因 Node 子进程 EPERM 假失败，那是环境限制不是代码 bug。

## 2. 每完成一件事，记录到 docs

**主档**：`d:\mlsstu\Desktop\SELF\docs\`（用户看的地方）

| 文件 | 记什么 |
|---|---|
| `工作记录.md` | AI / 助手做过什么：改了什么、怎么验证的、结果与遗留问题 |
| `想法记录.md` | 用户的想法、决策、偏好，尽量保留原话，标时间 |
| `漂流瓶岛-需求原档.md` 等 | 用户发来的长需求，逐字存档，不改写 |
| `想法与要求.docx` | 需求总档案（用户原有文件，不动） |

**git 副本**：`d:\mlsstu\Desktop\SELF\jenias-floating-world\docs\`

根目录 `docs/` 在 git 仓库**外面**，所以必须把整个 `docs/` 镜像进仓库，记录才能真正进 GitHub。写完主档立刻同步：

```
cp docs/*.md docs/*.docx jenias-floating-world/docs/
```

两边内容必须一致；提交前用 `cmp` 抽查。用户的想法也要记，不只是代码改动。

每条记录带日期时间，并按交付口径写三句：**改了什么 / 怎么验证的 / 哪里没覆盖**。

## 3. 三份交接文档

- `任务交接单.md` — **编号权威**（任务 prompt 从这里复制）
- `任务清单.md` — **状态权威**（勾选与执行顺序）
- `项目交接-给下一个AI.md` — 背景、数据契约、已知坑

根目录与 `docs/` 各一份，仓库内 `docs/` 再镜像一份；任何更新三处都要同步。

## 4. 交付口径（不变）

1. 先说结论，再说依据；中文，保留英文术语。
2. 一次只做一个任务，做完停下让用户看。
3. 遇到产品决策（岛名、文案、方向）给选项让用户选，不自己拍板。
4. 改完给三句话：改了什么 / 怎么验证的 / 哪里没覆盖。
5. 不虚构：没验证的就说没验证，没跑的就说没跑。
